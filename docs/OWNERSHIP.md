# 角色归属与章节隔离

## 不变量

- 专属卡牌与专属遗物由定义中的 `character` 指定拥有角色；没有该字段的是通用物品。升级不会改变归属。
- 新奖励同时检查角色、当前章和特殊生成限制。已拥有的合法旧牌可跨幕使用、升级、弃置与消耗。
- 十章对应十幕；每幕九层，共九十层。地图、工程决策、三步知识试炼和新卡奖励只引用本章，只有第十幕完成后才进入最终胜利。
- 每章提供三张通用基础知识牌，避免某个角色在特定章节没有三张合法候选；已有专属卡仍按其教材引用所在章节出现。
- 图鉴允许主动查阅所有章节和角色的卡牌；查阅不是获取，也不解锁当前远征中的其他角色物品。

## 已检查的入口

| 入口 | 规则与覆盖 |
| --- | --- |
| 起始牌组、起始遗物 | 三套固定十张牌；定义和升级归属逐项验证 |
| 普通、精英、首领战利品 | 使用当前章合法卡池；遗物来自通用奖励池；领取时再次检查 |
| 商店买牌与遗物 | 生成与购买分别校验；错误归属或仅特殊生成卡不花金币 |
| 宝箱 | 使用统一通用遗物池，一次性结算 |
| 事件 | 学习分支进入当前章题池；其他分支仅改资源，不暗中生成专属物品 |
| 工程决策 | 题目和迁移阶段属于当前章，不直接发卡或发遗物 |
| 知识试炼 | 发通用遗物；已全拥有时改发金币，待领奖结果持久化 |
| Banked Reset | 只有绿色未用重置额度能在过幕时生成；不能从商店和普通奖励取得 |
| 篝火升级 | 只升级本角色或通用卡；保留旧章合法牌的构筑 |
| 战斗使用 | 出牌、被动遗物、主动重置分别执行归属门控，不能依赖 UI 或新奖励过滤 |
| 保存与恢复 | 所有保存牌堆、已持有遗物、未领奖及商店一起处理，不重抽随机状态 |

`src/cards.ts` 的 `isCardForCharacter`、`canAcquireCard`、`isRelicForCharacter`、`rewardRelics` 是对应规则的统一入口。`src/engine.ts` 是唯一结算层，界面只作禁用与显示。

## 旧存档兼容

1. `src/save.ts` 先校验结构和题库修订。任意伪造奖励不能被当成旧版本奖励接受；只兼容精确的历史奖励公式。
2. `src/curriculum.ts` 将旧三幕存档接入当前正在学习的章节，保留当前位置、路线连接、资源、已答内容、知识和随机状态；未完成地图的知识引用统一到这一章。后续按十幕推进。
3. `src/ownership.ts` 统一转换历史跨角色物品。牌的 UID、升级、牌堆数量保留；专属攻击换通用攻击，能力换通用能力，零费技能换通用观测，其余技能换通用防御。未获取奖励还需符合当前章。
4. 已错误持有的其他角色遗物移除，每件补偿 60 金币；本角色专属及通用遗物保留。旧未领奖、旧商店改为合法通用候选或金币/售罄状态。
5. 旧战斗中来自非法专属能力的保留状态、行动连携记录会清理。发现非法力量来源时，当前战斗力量恢复为角色基础值；历史反复洗牌无法精确重建每次加成，不保留无法证明合法的持续增益。
6. 合法已拥有的 Banked Reset 保留；非法商店或奖励中的特殊生成牌转换。无绿色重置遗物的额度清零。
7. 转换不使用随机数。对已转换存档再次恢复不会重复补偿或生成物品。

新十幕存档使用 `curriculumVersion: 2`。标记存在时，跨章地图、当前决策或当前试炼不是合法状态；旧牌的知识引用不受此限制。

当前入门题库使用试炼 `revision: 3`。`beginner-migration.ts` 在结构与章节校验后，只替换旧存档中尚未作答的学习内容，并保持本章；已答题、地图、随机状态、资源、掌握度与合法物品不变。该迁移先于物品归属恢复，不能绕过卡牌或遗物限制。

关卡巩固题另用 `Battle.lab.followUpVersion: 1` 标记新衔接。没有标记且已答完第二步的入门旧档，继续使用原先的同知识点兄弟题和选项乱序，避免新题改变旧答案的解释。未答第二步可使用新的后续情境，作答时写入标记；恢复和重复作答不重新发奖励。该版本独立于三步试炼修订号，非法值拒绝恢复。

角色基础数值和起始牌组调整只影响新局，旧档已经保存的生命上限、最大能量、牌组与升级保留。卡牌效果、重置固定回复 30 生命、丝线每回合第三张牌只触发一次的规则由当前定义统一执行；新旧档都不按生命上限放大重置治疗。

## 验证入口

- `tests/ownership-audit.test.ts`：所有专属定义、全部角色组合、十二个种子下各获取入口、特殊生成及旧档残留效果。
- `tests/card-ownership.test.ts`、`tests/relic-ownership.test.ts`：用户截图对应的压缩牌和丝线遗物问题。
- `tests/curriculum.test.ts`、`tests/chapter-random.test.ts`：十幕逐章推进、三个试炼阶段、旧三幕兼容和跨章拒绝。
- `tests/expedition.test.ts`：三角色各十种子，正确/错误策略对比，全流程有限步结算、逐状态归属与保存恢复。
- `scripts/card-ownership-ui.js`、`scripts/relic-ownership-ui.js`、`scripts/character-kits-ui.js`、`scripts/curriculum-ui.js`：生产页面中的旧档恢复、实际使用、一次领取和桌面/手机布局。

最终整合验证已在另一个窗口完成后执行：22 个文件、101 项测试、类型检查和正式构建通过。三种角色各十种子均有可通关路线；当前固定策略错误决策 25/30 胜、正确应用 29/30 胜。完整过程记录于 `TDD.md`。

## 章节事件新增入口

第三章检索事件仅展示 `canAcquireCard` 允许的本章、本角色新牌；第十章资源交换仅使用未拥有的通用遗物。删牌、升级、回滚和同名整合只操作当前角色合法实体，保留旧章节牌的使用权。事件获取与原有商店/奖励/试炼共同接受角色与章节检查，三角色遍历十章结算的矩阵测试会逐次存档重读。
